01 / WHY ZCACHED

The essentials.
Nothing soft in the middle.

Designed as infrastructure, not a framework: explicit limits, predictable recovery, and tools that tell you exactly what the server is doing.

01

Native, not abstracted.

io_uring on Linux. kqueue on macOS. Cooperative connections keep throughput high without a thread explosion.

02

Durable by default.

Atomic CRC-checked snapshots and a crash-safe AOF. Recovery order is documented, not discovered.

snapshot → AOF → ready
03

Permissions with shape.

Token principals, command groups, read/write/delete prefixes, rate limits and live revocation.

app:*readwritedeny FLUSH
04

Observable under load.

Atomic counters in INFO, explicit resource errors, protocol metrics, and backpressure boundaries.

04 / QUICKSTART

From clone
to cache.

Build the server, launch it, and use the dedicated CLI. Authentication is optional for local development and explicit for production.

  • ✓ Zig 0.17.1
  • ✓ Linux or macOS
  • ✓ OpenSSL only for TLS builds
# Build optimized binaries
git clone https://github.com/sectasy0/zcached
cd zcached
zig build -Doptimize=ReleaseFast

# Run and connect
./zig-out/bin/zcached
./zig-out/bin/zcached-cli PING
# Start the packaged server
docker compose up

# Talk to port 7556
zcached-cli --host 127.0.0.1 PING

# Persist /var/lib/zcached in production
# Generate a cryptographically secure token
zcached-cli token generate --hash

# Add a constrained principal
zcached-cli auth add --file ./auth.zon \
  --id application --token "$TOKEN" \
  --groups basic,diagnostic --read "app:" \
  --write "app:"
